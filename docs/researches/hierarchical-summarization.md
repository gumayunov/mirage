# Иерархическая суммаризация + граф сущностей — разведка

Дата: 2026-04-15
Статус: research / idea

## Идея

Древовидная структура суммаризаций: чанки → главы → части → книга. На каждом
уровне извлекаются сущности и факты, которые связывают разрозненную
информацию между ветвями дерева.

Цель — при запросе уметь отвечать не только по локальному чанку, но и
«собирать» информацию о сущности через всю книгу.

## Существующие подходы

### Дерево суммаризаций (без акцента на сущности)

- **RAPTOR** (Stanford, 2024) — ровно такая структура: чанки кластеризуются,
  каждый кластер суммаризируется, рекурсивно вверх до корня. При поиске
  обходят все уровни дерева.
  - Реализация: `parthsarthi03/raptor`, `RaptorPack` в LlamaIndex.
- **LlamaIndex TreeIndex / DocumentSummaryIndex** — более простая
  древовидная суммаризация, давно в проде.

### Граф сущностей и фактов

- **Microsoft GraphRAG** — самое близкое к описываемой идее. Извлекает
  сущности и связи → строит граф → кластеризует через Leiden на нескольких
  уровнях иерархии → генерирует **community reports** для каждого уровня.
  При запросе выбирается подходящий уровень детализации.
  Фактически дерево суммаризаций, где узлы — сообщества сущностей.
- **LightRAG** (HKU, 2024) — упрощённая версия GraphRAG, dual-level
  retrieval (локальные сущности + глобальные темы). Дешевле в индексации.
- **HippoRAG / HippoRAG 2** (OSU, 2024–2025) — граф знаний + Personalized
  PageRank, вдохновлено гиппокампом. Хорошо решает задачу «связать
  разрозненную информацию».
- **nano-graphrag** — минималистичная реализация GraphRAG, удобна для
  понимания механики и адаптации под свой код.

### Гибриды (RAPTOR + entity linking)

Прямо готовой системы «из коробки» нет, но это активный research frontier.
Встречались работы: **SiReRAG** (2024), **HiRAG** (2025) — комбинируют
иерархию суммаризаций с графом сущностей.

Описанная идея — естественный шаг: RAPTOR даёт структуру, GraphRAG даёт
связность через сущности.

## Применимость к miRAGe (книги)

Для книг иерархия уже есть естественно: книга → часть → глава → раздел →
параграф. Не нужно кластеризовать вслепую, как в RAPTOR.

Сущности (персонажи, места, концепции) дают cross-references между главами.
Решает классический провал RAG: «герой упомянут в главе 3 и главе 17,
обычный retrieval вернёт только одну».

## Практический путь

1. Взять структуру книги как готовую иерархию (вместо кластеризации).
2. Суммаризация снизу вверх: параграф → раздел → глава → часть → книга.
3. На каждом уровне — extraction сущностей и фактов. Накопление снизу
   вверх: список сущностей главы = объединение сущностей её разделов.
4. При retrieve: гибрид — векторный поиск по суммаризациям на нужном
   уровне + обход графа сущностей для cross-references.
